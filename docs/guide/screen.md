# Руководство автора экрана

Экран — это кадр макета, собранный виджетами. Макет —
[docs/visual/carrel-ui-mockups.html](../visual/carrel-ui-mockups.html), его
правила — [docs/visual/mockup.md](../visual/mockup.md), виджеты — пакет
`widget` ([спека](../spec/typecase.md)). Руководство одно для демо-экранов
Typecase (`internal/screens`) и для экранов приложения (Carrel).

## 1. Начни с кадра

Найди кадр экрана и его `data-frame` (`s-find-2`, `desktop-10`). Нет кадра —
нет экрана: сначала кадр в макете (шаг 4).

Какие кадры — экраны, решено в Р-16 ([development.md](../development.md)):
кадры с пометкой «компонент», «фрагмент», «список», «меню» — записи
каталога, не экраны.

## 2. Черновик — `frame2go`

```bash
go run ./cmd/frame2go s-find-2
```

печатает функцию экрана: виджеты кадра сверху вниз, варианты по классам
кадра, данные кадра как есть. Черновик уже совпадает с кадром — статическая
сверка его принимает. Из модуля приложения — тот же генератор из модуля
Typecase:

```bash
go run carrel.dev/typecase/cmd/frame2go -self -root "$(go list -m -f '{{.Dir}}' carrel.dev/typecase)" s-find-2
```

(копия макета в приложении совпадает с копией в Typecase побайтно, так что
кадры те же). С `-self` черновик — целый файл: `package draft`, импорт
`widget` и всё, что ему нужно, — и собирается в модуле приложения без
демо-экранов Typecase.

Если кадр не переводится, `frame2go` называет элемент, которого не знает. Это
пробел — шаг 4.

## 3. Данные — из приложения

Где в кадре данные, а где разметка, генератор не знает. Это решает автор:

- строки списка, таблицы, дерева — цикл по модели; одна строка кадра — образец
  строки;
- числа, имена, даты, счётчики — поля модели;
- состояния — загрузка, ошибка, пусто — по их кадрам: у каждого состояния свой
  кадр, у каждого кадра свой черновик;
- всё остальное — поля виджетов, как в черновике: варианты, места, подписи
  кнопок;
- адреса, методы, имена полей — тоже поля виджетов (Р-25): `Href` у кнопки,
  строки, пункта меню и узла дерева, `Action` и `Fields` у формы (CSRF —
  скрытым полем), `Name` у поля, отметки, сегмента и выбора. Кнопке вне формы,
  которая отправляет POST, — `Form` с именем `PostForm`, напечатанной в конце
  страницы. Черновик этого не знает: кадр рисует вид, а смысл — из модели.

На экране нет CSS, `style=`, классов `tc-*` руками. Узкий вид на экране не
проектируется: он уже в макете. Если на узкой ширине экран плох — правка в
макете, на всех экранах сразу.

## 3½. Страница целиком

Экран — это корень библиотеки; документ вокруг него — `page.Document`:

```go
doc := page.Document{Title: "Contacts", Assets: page.At("/static/tc"), Root: screen, Forms: forms}
html, err := doc.Render()
// и один раз: mux.Handle("/static/tc/", http.StripPrefix("/static/tc", page.Static()))
```

Голову, спрайт и сценарии пишет библиотека; своей разметки на странице нет.

## 4. Не собирается — это пробел

Пробел — не повод для обхода на экране. Порядок один:

1. кадр или фрагмент в макете — по разделу «Как менять макет»
   [mockup.md](../visual/mockup.md#как-менять-макет), со сверкой «до/после»;
2. новая копия макета в Typecase (и в приложении — побайтно);
3. вырез CSS (`go generate ./css`);
4. виджет с эталоном — запись в `internal/refs`, фрагмент кадра, ворота
   ([development.md](../development.md), «Виджет, вариант, поле»);
5. экран.

Пока пробел открыт, кадр записан в
[docs/visual/gaps.md](../visual/gaps.md): кадр и чего не хватает.

## 5. Проверка

- `go test ./...` — статическая сверка: дерево экрана равно дереву кадра, те
  же виджеты в том же порядке (`internal/screens`, `TestFramesStatic`).
  Демо-экраны Typecase — вывод `frame2go` как есть: изменился кадр —
  `go generate ./internal/screens`, руками их не правят (`TestGenerated`).
- Смысл: у каждого нажимаемого есть поле, куда он ведёт или что отправляет
  (Р-25, Р-27) — `Href`, `Form`/`To`/`Name`/`Value`, `Send` у галок, `Action`
  у форм, поиска и фильтра, `Name` у полей. Экран, где оно пусто, по виду
  собран, а без сценариев не работает. Поле, отметка или пункт меню с `Name`
  вне формы, которая отправляет, называют свою форму: `Send.Of` у галки,
  `MenuItem.Of` у радио меню — выбор коллекции в шапке правки стоит вне её
  формы (задача 203).
- В приложении — сверка устройства (пакет `shape`): экран с данными приложения
  и его кадр — те же элементы в том же порядке, те же классы и состояния; слова
  и данные не сравниваются; ряд одинаковых строк может быть длиннее, но не
  короче, и всё, что кадр рисует в ряду, на экране есть (задача 76: пропавшая
  кнопка, секция, кусок значения краснеют); повтор блоков — месяцы, дни с событиями,
  поля — любой длины (задача 61); содержимое `<template>` и `<datalist>`
  (варианты строки ввода, задача 146) не сравнивается;
  а смысл HTML (ссылка вместо кнопки, `select` вместо выбора, Р-25) —
  не расхождение:

  ```go
  m, _ := shape.Parse(mockupHTML)
  err := m.Check("s-find-2", screen.Render())
  ```

- С Chrome — лестница ширин: кадр и экран на десяти ступенях, коробки, шрифт,
  цвет, инварианты (нет прокрутки вбок, лист сверху, зона нажатия 44 px):
  `go test ./internal/browser -run TestFrames`.
- Посмотреть глазами — снимок кадра и экрана
  ([mockup.md](../visual/mockup.md#как-менять-макет), «Посмотреть глазами»;
  демо — `go run ./cmd/screens`, `/f/<data-frame>`).
