# Разработка Typecase

Как устроена библиотека и как с ней работать. Рядом:

- [spec/typecase.md](spec/typecase.md) — спецификация: что библиотека обещает (L-…);
- [visual/mockup.md](visual/mockup.md) — правила макета: словарь, узкие экраны, проверки, как менять;
- [guide/screen.md](guide/screen.md) — руководство автора экрана;
- [roadmap.md](roadmap.md) — что впереди и что открыто;
- [../CHANGELOG.md](../CHANGELOG.md) — что изменилось по выпускам.

## Как устроено

Вид берётся из макета, и между макетом и библиотекой нет перевода. Держится
это на четырёх вещах, и все четыре проверяет код.

1. **CSS один.** `css/typecase.css` — дословный вырез блока `<style data-tc>`
   из копии макета `docs/visual/carrel-ui-mockups.html` (`go generate ./css`,
   `internal/mockcss/cut`). Ворота `css-from-mockup` сверяют вырез с файлом
   байт в байт; правило CSS вне `css/`, чей объект — класс `tc-*`, красное.
   Спрайт `icons/sprite.svg` вырезается тем же шагом.
2. **Виджет печатает фрагмент своего кадра.** У каждого виджета есть эталон —
   запись `internal/refs`: виджет, данные из кадра и адрес
   `Ref{Frame, Class, N}` (кадр, класс блока, номер вхождения). Тест сверяет
   дерево `Render` с деревом фрагмента: тег, классы, текст, значения полей,
   значки, `data-tc-*`. У каждой формы блока в макете есть запись
   (`TestShapesCovered`), у каждого экспортируемого виджета — эталон.
3. **Контейнер принимает только то, что макет в него кладёт.** Пары
   «блок-родитель → блок-ребёнок» выведены из всех кадров; слоты — интерфейсы
   с неэкспортируемым методом. Вложение, которого макет не рисует, не
   компилируется, и лишнее разрешение красное (ворота `container-pairs`).
4. **Экран — кадр, собранный виджетами.** Демо-экраны `internal/screens` —
   вывод генератора `cmd/frame2go`; статическая сверка держит всё дерево
   экрана равным кадру, браузер — коробки на лестнице ширин.

Одинаковый CSS и одинаковое дерево дают одинаковую картинку, поэтому сверка
виджета статическая. Браузер нужен там, где вид зависит от поведения
(`tc.js`, замеры, фокус) и от ширины.

Как библиотека читает кадр — блок, элемент, примеси, рамка настольного окна —
в [mockup.md](visual/mockup.md), «Как библиотека читает кадр».

## Как вносить изменения

**Всегда в этом порядке: макет → CSS → виджет → экран.** Недостающее сначала
рисуется кадром; на экране нет CSS, `style=` и классов `tc-*` руками.

### Вид или новый кадр

1. Правка в макете по разделу «Как менять макет» [mockup.md](visual/mockup.md).
   Новый кадр получает следующий номер своего раздела.
2. Правка CSS в блоке `data-tc` → `go generate ./css`.
3. Видимое отличие существующего кадра человеку показывают снимками
   «до/после» (ниже, «Посмотреть глазами») и говорят, куда смотреть в
   кадре; принятое называет сообщение коммита — кадры и чьё решение.
   Таблицы отличий нет (Р-52). Перед коммитом — `TestMockupStrays`: кадр,
   который изменился, хотя его не правили, либо чинится, либо показывается
   человеку вместе с задуманными.
4. Эталоны, чей фрагмент изменился, поправить в `internal/refs`; новая форма
   блока — новая запись (`go run ./internal/fragment/cmd/shapes tc-…` печатает
   формы).
5. `go generate ./internal/screens` — экраны заново.
6. Что из правки касается сервера и клиента — записка в Carrel
   `docs/plan/from-typecase.md` с последним коммитом Typecase, который она
   описывает. Копию макета в Carrel эта сессия не трогает: её переносит
   переход клиента на коммит Typecase одним шагом с тем, что она требует
   (решение человека 2026-10-02, Carrel `4cd37cf`).

### Виджет, вариант, поле

- API — из фрагмента: поля — переменные части кадра; имена Go — из имён CSS
  (`tc-tickrow` → `TickRow`, `__title` → `Title`); варианты блока — одно
  поле-перечисление; взаимоисключающие состояния — перечисление, `bool` —
  только независимый признак. Перечисление печатает свои классы методом
  `class()` — по этим таблицам генератор экранов выбирает вариант.
- Комментарий виджета — восемь пунктов L-3.2 (роль, вход, состояния,
  инварианты, поведение, эталон, содержимое, чего нет); раздел L-4 спеки
  совпадает с ним (ворота `doc-format`, `spec-l4`).
- Состояние из описания — запись эталона с тем же именем (ворота `catalog`);
  каталог строится из эталонов.
- Генератор (`internal/framegen`) узнаёт новые классы и атрибуты; элемент,
  которого он не знает, останавливает кадр с его именем.

### Экран

По [руководству автора экрана](guide/screen.md): кадр → `frame2go` → данные
приложения. Демо-экраны руками не правят: изменился кадр —
`go generate ./internal/screens` (`TestGenerated`).

### Пробел

Кадр не собирается из виджетов — это пробел, а не повод для обхода: кадр или
фрагмент в макете, копия, вырез CSS, виджет с эталоном, экран. Пока пробел
открыт, кадр записан в [gaps.md](visual/gaps.md).

## Проверки

- **Без браузера** (`go test`): ворота L-8 (`internal/gate`, таблица — L-8
  спеки), эталоны (`TestWidgetFragments`, `TestShapesCovered`), статическая
  сверка экранов с кадрами (`TestFramesStatic`), экраны — вывод генератора
  (`TestGenerated`), линт макета.
- **В браузере** (`internal/browser`, нужен Chrome или Edge): лестница ширин —
  кадр и экран на десяти ступенях (1351 / 1191 / 1190 / 1008 / 1007 / 820 /
  641 / 640 / 460 / 390), коробки с допуском 0.5 px, вычисленный стиль;
  инварианты экрана (нет прокрутки вбок, соседи не перекрываются, лист
  сверху, текст в коробке, зона нажатия 44 px); длинные подписи; эмуляция
  планшета; печать; поведение `tc.js`; каталог. У каждой проверки есть укус
  (L-9.3).
- Исключение сверки в браузере одно: внутренность `input[type=date|time]`
  (браузер рисует своё; коробка сравнивается). Замеры синхронные, без
  `setTimeout`: в фоновой вкладке Chrome душит таймеры. Кадр и экран — с одного
  сервера и на одних шрифтах.
- **Неожиданные сдвиги** (`TestMockupStrays`, Р-52) — рабочий макет против
  `HEAD`. Кадр, чей HTML изменился, — задуманное отличие: он назван и не
  меряется. Кадр с тем же HTML мог измениться только через CSS или спрайт:
  не менялись они — браузер не запускается; изменилось правило — кадры, до
  которых дотягиваются его селекторы, меряются на всех ступенях лестницы
  (коробка и все вычисленные свойства каждого узла), и отличившийся кадр
  красный. Правило без класса и атрибута (`:root`, тег, `@font-face`), другой
  порядок правил, спрайт — меряются все кадры, до получаса.
- Перед коммитом прочитать вердикт проверок целиком, а не через обрезку
  вывода: однажды красная лестница спряталась за `tail`.

## Выпуск

- Выпуск — коммит `typecase/vX.Y.Z: <что>` и раздел `## typecase/vX.Y.Z — дата`,
  вырезанный из `## Unreleased` в CHANGELOG. Константы версии в коде нет,
  тегов нет (решение человека 2026-09-27; Carrel подключит Typecase, когда
  появится первый экран клиента, — тогда нужен тег или `replace`).
- Перед выпуском — всё без браузера и браузер целиком.
- Коммиты — прямо в `main`. В origin (`gitea.mixdep.ru`) — только с согласия
  человека.
- В Carrel коммитят только записку (`docs/plan/from-typecase.md`), с согласия
  человека: там обычно лежит незакоммиченная работа других сессий. Копию
  макета, `to-typecase.md` и прочие файлы Carrel не трогают (2026-10-02).

## Решения

Решения человека, принятые в планах 2–4 (2026-09-23 — 2026-09-27). Решения
плана 1 (Р-1, Р-3, Р-4, Р-6…Р-14, Р-21) — в [mockup.md](visual/mockup.md).

- **Р-2. Пакета `layout` нет.** Сужение живёт в CSS макета (контейнеры
  `tcbox`, лестница ширин) и в состояниях оболочки (Р-3); `tc.js` читает режим
  из `--tc-shell-mode`, своих порогов не держит.
- **Р-5. Ломающие выпуски без переходного слоя.** До 1.0 ломающее изменение —
  в минорном выпуске, без периода устаревания и руководства по переходу;
  старые виджеты, CSS и ворота удаляются целиком.
- **Р-15. Виджета без кадра нет.** Каталог — только то, что нарисовано;
  дубли удалены, остальное сопоставлено кадрам (2026-09-26).
- **Р-16. Какие кадры — маршруты.** Кадр без пометки «компонент»,
  «фрагмент», «список», «меню», «кандидат» — маршрут демо `/f/<data-frame>`;
  меню приложения и трея (`desktop-2`, `desktop-8`) — каталог. Помеченные
  — записи каталога рядом с виджетами, которыми собраны; кандидаты не
  показываются нигде.
- **Р-17. Интерфейс Carrel начинается на 0.7.0** по руководству автора
  экрана, без перевода старых экранов.
- **Р-18. Данные без `style=`.** Цвет и доля — атрибутами `data-tc-colour`,
  `data-tc-width`; `tc.js` ставит `--tc-colour`, `--tc-width` через CSSOM
  (CSP Carrel без `unsafe-inline`).
- **Р-19. Библиотека общего назначения.** Макет — визуальный источник,
  содержимое кадров — примеры; имена по роли, без доменных слов (L-2.2).
- **Р-20. Вырез CSS лежит файлом** `css/typecase.css` (исключение L-11.1):
  его сверяют с макетом байт в байт.
- **Р-22. Замена адреса в карточке** — лист предлагает переписать адрес в
  записях, где человек участник, и называет последствия (`s-contacts-15`),
  итог — на карточке (`s-contacts-16`).
- **Р-23. Сервер без пароля** — отметка в форме подключения выключает поле
  пароля (`s-profile-14`); пустое активное поле значит «не менять».
- **Р-24. «Упоминания» отложены** — см. [roadmap.md](roadmap.md).
- **Р-25. Смысл HTML — данные виджета** (2026-09-28, задача 29 сервера
  Carrel): адрес, метод, имя и значение — поля виджетов (`Button.Href`, `Form`,
  `To`, `Name`/`Value`; `Form.Action`/`Method`/`Fields`; `Name` у `Check`,
  `Seg`, `Pick`; `Href` у строк, пунктов меню, узлов дерева), и виджет печатает
  из них `<a>`, `<form>`, флажок, радиокнопку, `<select>`, скрытое поле. Каждая
  форма нарисована один раз — кадры `components-37`…`-39`; экранные кадры
  смысла не повторяют. POST вне формы — кнопка с атрибутом `form`, форма
  `PostForm` без видимых полей стоит где угодно на странице: у кнопки нет
  обёртки, и вложенность контейнеров не меняется. Флажок и сегмент рисуют
  состояние своей кнопки формы через CSS — работают без сценариев. Поведение
  сверх того — атрибутами `data-tc-*` из данных (`Disables`, `Follows`, `Adds`,
  `Theme`, `Drop`), и у каждого есть путь без сценария: сервер отвечает формой, лист
  открывается адресом, импорт остаётся кнопкой.
- **Р-27. Смысл у всего, что нажимают** (2026-09-29, задача 39 сервера
  Carrel): у каждой кнопки, ссылки, «ссылки по виду», галки, поля и строки
  запроса есть поле смысла, и это проверяет машина —
  `TestEveryControlHasMeaning` (`internal/refs`) заполняет поля смысла у всех
  эталонных записей и называет элемент, который всё равно никуда не ведёт и
  ничего не отправляет, с кадром. Галка — либо кнопка отправки, действующая
  сразу, либо флажок формы до действия (`Send`); заголовок меню — строка, а
  не кнопка.
- **Р-26. Корень страницы — пакет `page`** (2026-09-28, задача 38 сервера
  Carrel): документ вокруг экрана печатает библиотека — голова (тема и стили
  подключением, без встроенных блоков: политика `script-src 'self';
  style-src 'self'`), спрятанный спрайт, один корень библиотеки
  (`widget.Root` — закрытый интерфейс: оболочка, страница, наложение) и
  формы `PostForm`. У приложения нет места для своей разметки; файлы
  библиотеки отдаёт `page.Static()`.
- **Р-28. Два сценария: ядро и живой слой** (2026-10-02, поправка L-1).
  `tc.js` — ядро: без сети и без хранилища, только поведение разметки.
  `tc-live.js` — необязательный живой слой: меняет страницу без перезагрузки,
  спрашивая только адреса, которые называет разметка (`data-tc-suggest`,
  `data-tc-swap`, `data-tc-progress`); без него каждое такое место — простая
  ссылка или форма. Страница работает и без обоих.
- **Р-29. Правка не перезагружается; файл уходит по Save** (2026-10-02).
  Правка любой записи посреди работы не перезагружается: файл и фото — поля
  её формы и уходят вместе с карточкой по Save (`FileField.List`,
  `MenuItem.Row`, `FileField.Preview`); выбранный файл стоит строкой среди
  вложений с Remove, без пометки «не сохранено» — в правке не сохранено всё;
  Save с файлами показывает прогресс (`Runbar.Progress`). Сразу файл уходит
  только там, где правки нет (`FileField.Form` или `To`). Поведение во всех
  правках одинаковое.
- **Р-30. Без сценария** (2026-10-02, задачи 104, 109). Полоса правки
  (`Docbar.Edit`) без сценария — только Save и Cancel: разметку пишут
  обычным Markdown руками. На странице чтения всё, что переключает вид, —
  ссылки (`?view=source`, `?width=…`, `?side=0`), и перезагрузка там
  допустима; живой слой подменяет колонку на месте (`Swap`). Меню, «⋯»,
  выбор и раскрытия открываются без сценария (`details`).
- **Р-31. Отказ источника** (2026-10-02): в рейле — только значок, причина в
  его подсказке; в полосе опроса — красная «N failed» с меню: что спросили,
  что ответил сервер, Retry источника и Retry all. Слово — «failed».
- **Р-32. Счёт и размеры — только известные** (2026-10-03, задача 128):
  счёт элементов папки и размеры картинки показываются, только если они уже
  известны без своего запроса; иначе — «folder» и пустая подпись плитки.
- **Р-33. Обмен с Carrel** (2026-10-02, Carrel `4cd37cf`): в Carrel кладётся
  только записка `docs/plan/from-typecase.md` с последним коммитом Typecase;
  копию макета переносит переход клиента.
- **Р-34. Счёт и «ro» — раздельно** (2026-10-07, задача 105): в рейле счёт
  стоит на месте счёта (у снятой строки — «—»), доступ только для чтения —
  бейджем «ro» рядом, у подписок тоже; одно другое не заменяет.
- **Р-35. Папки с датами лежат в `attachments`** (2026-10-07, задача 121):
  `Documents / carrel / attachments / 2026-07`; деревья листов, крошки и
  отказ занятого имени рисуют так.
- **Р-36. Copy говорит «Copied»** (2026-10-07, задача 118): нажатая кнопка
  на мгновение меняет слово; правый край её стоит, она растёт влево с
  обычными полями — кнопки после неё не сдвигаются (`Button.Copied`).
  Места под второе слово заранее не держат: поля кнопки от этого другие.
- **Р-37. Сервер — в шапке листа, остальное — в дереве** (2026-10-07,
  задача 120): в листах загрузки, переноса, копии и From Files сервер

Закрытые решения о сверке:

| Решение | Почему |
|---|---|
| Эталон — `Ref{Frame, Class, N}`; `N` с 1, подпись кадра не ищется | Адрес без селекторного движка |
| Данные эталона — данные кадра | Сверка честная, только если данные те же |
| Сравниваются тег, классы, текст (у `pre-wrap` — как есть), у `input` — `type`, `value`, `placeholder`, `disabled`, `checked`, у `button`/`textarea` — `disabled`, у `svg` — `viewBox`, размеры, обводка, у `use` — `href`, `data-tc-*`, `colspan`, `rowspan`; не сравниваются `aria-*`, `role`, `id`, `for`, `title`, `href` ссылок, `type` кнопки | Сравнивается то, что меняет картинку; доступность виджет добавляет сверх кадра |
| Разбор макета — `golang.org/x/net/html`, только во `internal`; генератор — свой токенизатор | Потребитель получает код без зависимостей (L-11.1); генератору нужны пробелы между строчными элементами и атрибуты без значения |
| `tc.js` и крючки `data-tc-*` — контракт | Поведение проверено тестами |
| Шрифты — свой `css/fonts.css` на `fonts/` | `@font-face` макета указывает на файлы рядом с макетом |
