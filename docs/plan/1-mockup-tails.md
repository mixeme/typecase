# Хвосты макета

Что осталось после плана «Макет — единственный источник вида» (закрыт
2026-09-21, выпуск 0.6.0). Правила макета — в
[docs/visual/mockup.md](../visual/mockup.md); этот файл — только незакрытое.
Найдено проверкой закрытого плана: линт зелёный, но часть пунктов выполнена
по букве, а не по цели.

Порядок: до шага 1 плана [2-library-from-mockup](2-library-from-mockup.md).
План 2 вырезает `<style data-tc>` дословно и сверяет виджет с фрагментом кадра
по классам — всё, что здесь не закрыто, уедет в библиотеку как есть.

Правки макета идут по разделу «Как менять макет» `mockup.md`: правка в Carrel,
копия в Typecase целиком, линт, сверка «до/после», запись в
`allowed-diffs.md`. Х-1, Х-2 и Х-4 требуют решений человека — исполнитель
собирает список и ждёт «да».

- [ ] Х-1 — нумерованные классы `--rN`
- [ ] Х-2 — правила, удалённые замком как мёртвые
- [ ] Х-3 — витрины `.demo`
- [ ] Х-4 — пустые правила `{}`
- [ ] Х-5 — `style=` на странице
- [ ] Х-6 — CI

## Х-1. Нумерованные классы `--rN`

Шаг 5 закрытого плана требовал: повторяющаяся правка (≥2 кадра) → вариант
блока с именем по смыслу (`tc-sheet--narrow`, `tc-head--snug`); разовая
(Р-13) → подтянуть к ближайшему классу, видимые изменения — списком человеку.
Сделано иначе: скрипт `internal/mockcss/inline` перенёс каждую разную строку
`style=` в класс с номером.

Цифры на закрытии: **596** правил вида `.tc-x--rN.tc-x--rN{…}`, 1690
употреблений в разметке; 323 правила употреблены один раз, 273 — два и больше
(`tc-span--r15` — 63 раза, `tc-field--r4` — 59, `tc-span--r19` — 34,
`tc-mark--r1` — 31). **191** правило висит на «блоке», которого нет, — имени
тега: `tc-div` (120), `tc-span` (51), `tc-ul` (6), `tc-b` (5), `tc-td` (4),
`tc-tr` (2), `tc-p`, `tc-li`, `tc-strong`, `tc-dd`.

Почему это хвост, а не вкус:

- Р-6 не выполнено: `tc-div--r37` — не блок, не элемент и не вариант.
- Цель плана — «кадр и экран отличаются только тем, кто напечатал разметку».
  Виджет плана 2 сверяется с фрагментом кадра по классам, значит либо печатает
  `tc-span--r15`, либо сверка красная. План 2 про `--rN` не знает.
- CSS библиотеки получит 596 правил-номеров с удвоенной специфичностью.

Что сделать:

- [ ] Отчёт: каждое `--rN` — объявления, сколько раз, в каких кадрах, на каком
      элементе какого блока. Основа — `docs/visual/inline-audit.md`.
- [ ] Повторяющиеся с одним смыслом → вариант или элемент блока с именем
      (`color:var(--tc-dusty)` на подписи → элемент блока, а не `tc-span--r15`).
      Имя тега вместо блока не остаётся нигде: узел получает имя элемента того
      блока, в котором стоит.
- [ ] Разовые → по Р-13: убрать, подтянув к ближайшему классу. Список кадров с
      видимым изменением — человеку; каждое «да» — строкой в `allowed-diffs.md`.
- [ ] Клей раскладки, спрятанный в `--rN` (`display:flex;gap:…`), → компоненты
      клея из `mockup.md`, других не заводить.
- [ ] Линт: правило `no-numbered-classes` — в кадрах и в `data-tc` нет
      `--r\d+`.
- [ ] План 2, шаг 2: сверка фрагмента исходит из того, что `--rN` нет.

## Х-2. Правила, удалённые замком как мёртвые

Шаг 8 удалил правила `data-tc`, которые не срабатывали ни в одном кадре.
Часть из них — не мусор, а состояния, которые макет не нарисовал:

| Правило | Значение | Чего не хватает |
|---|---|---|
| `[data-tc-theme="dark"] .tc-avatar` | `background:#3A463D;color:#C9BFA6` | тёмного кадра с аватаром |
| `[data-tc-theme="dark"] .tc-thumb` | `background:#33403A` | тёмного кадра с плитками файлов |
| `[data-tc-theme="dark"] .tc-scrim` | `background:rgba(0,0,0,.42)` | тёмного кадра с листом |
| `.tc-badge.is-plan` | `border-style:dashed` | кадра с таким значком |
| `.tc-table td.is-idle` | `color:var(--tc-dusty)` | кадра с такой ячейкой |
| `.tc-queue.is-min ul` | `display:none` | кадра со свёрнутой очередью |
| `.tc-shell__body--no-rail.tc-shell__body--side` | `grid-template-columns:minmax(0,1fr) var(--tc-side)`; в `rail` — `minmax(0,1fr)` | кадра без рейла с панелью |
| `.tc-table__col--w34` | `width:34%` | — (похоже на настоящий мусор) |

Тёмный кадр в макете один (календарь), а решение «любой кадр можно показать
тёмным одним атрибутом» осталось: сейчас тёмные аватар, плитка и затемнение
в продукте получат светлые значения.

- [ ] По каждой строке — решение человека: нарисовать кадр (правило
      возвращается вместе с ним) или состояние не существует.
- [ ] Для тёмной темы — минимум кадров, на которых срабатывают все
      `[data-tc-theme="dark"]`-правила: контакты, плитки файлов, лист.
- [ ] `mockup-parity` потерял пару «без рейла + панель»
      (`internal/gate/mockup_parity.go`); `layout.ShellNoRailHasSide` с макетом
      не сверяется. Закрывается либо кадром, либо удалением `layout` на шаге 6
      плана 2.

## Х-3. Витрины `.demo`

В разделе компонентов 27 блоков `.demo`. Линт считает их продуктом для
`dead-rules`, но не проверяет остальными правилами кадров.

- 54 правила `data-tc` живы только благодаря витринам: настоящие компоненты,
  которых нет ни в одном кадре (`.tc-split`, `.tc-head__group`,
  `.tc-drop.is-bar`), и около пятидесяти `--rN` раскладки самих витрин
  (`tc-root--r1…r19`, `tc-div--r2…r7`), которые уедут в CSS библиотеки.
- В витринах остались безымянные узлы, которые в кадрах уже названы: `<ul>` и
  `<span>` в `.tc-queue` (в кадре — `tc-queue__list`, `tc-queue__name`,
  `tc-queue__meta`).
- `style=` на `.demo` (`gap:22px`) и на восьми подписях `.sub`.
- `data-demo="m-btn m-seg …"` на 34 узлах (витрины и кадры-компоненты)
  перечисляет старые имена `m-*`; атрибут никто не читает. Либо перевести по `rename.tsv`, либо удалить.
- Класс страницы и класс продукта на одном узле: `class="demo tc-root col"`.

- [ ] Решить одно из двух: витрина — это кадр (`.frame` с `data-frame`, весь
      линт, попадает в каталог по Р-16 плана 3) или страница (её раскладка — в
      `<style>` страницы, `dead-rules` её не считает).
- [ ] Компоненты, живущие только в витринах, — в кадр или под решение Х-2.

## Х-4. Пустые правила `{}`

Чтобы пройти `classes-defined`, шаг 8 добавил правила без объявлений:
`.tc-shell,.tc-row__lead,.tc-row__due,.tc-row__date,.tc-row__size,.tc-head__text,.tc-docmeta__sec,.tc-queue__list,.tc-queue__name,.tc-queue__meta,.tc-row__file,.tc-menu__label,.tc-auth__tagline,.tc-auth__link,.tc-print__cell,.tc-msg__aside,.tc-stack__item,.tc-sheet__block,.tc-line__item{}`,
`.mk-status__text{}`, `.mk-dot{}`. Там же `.tc-rubric__aside{flex:none}` стал
`.tc-rubric__aside{}` — класс раздали безымянным `span` рубрик, и объявление
сняли, чтобы сверка осталась нулевой.

- [ ] Решить: имя без правила — законно (тогда `classes-defined` читает список
      имён-без-стиля, а пустые правила уходят из `data-tc`) или у каждого имени
      есть объявление.
- [ ] `.tc-rubric__aside`: вернуть `flex:none` там, где оно было нужно, под
      отдельным именем, либо подтвердить, что оно ни на что не влияло.
- [ ] `tc-stack__item` и `tc-line__item` розданы как имя «хоть какое-нибудь»
      (пустой `span` в ячейке таблицы, подпись `verified`) — пройти по
      употреблениям вместе с Х-1.

## Х-5. `style=` на странице

Цель говорила «ни одного `style=`», линт проверяет только кадры. Вне кадров —
142 атрибута в тексте разделов и таблицах `table.doc`, плюс 21 на самих
`.frame` (`width:392px`, `max-width:900px`…). Инлайновый `max-width` на `.frame`
сильнее правила переключателя лестницы (`width:…!important;max-width:100%`):
11 кадров с `max-width` на странице не растягиваются до выбранной ступени.

- [ ] Ширины кадров — классами страницы; проверить переключатель на этих
      кадрах.
- [ ] Остальное — по желанию: это оформление страницы, на продукт не влияет.

## Х-6. CI и обвязка браузерных тестов

- [ ] `TestMockupLadder` (до 40 мин) и `TestMockupRefactor` (до 35 мин) стоят в
      `go test ./internal/browser` с таймаутом по умолчанию 10 мин. Вынести в
      отдельную задачу с `-timeout 60m` или запускать только при изменении
      `docs/visual/carrel-ui-mockups.html`.
- [ ] Сверка «до/после» виснет по таймауту, а не по пикселям. На закрытии: полный
      прогон дал 10 таймаутов из 165 кадров, повтор — другие кадры; после
      остановки трёх осиротевших headless-Edge (профиль `typecase-browser-*`)
      все упавшие кадры прошли по одному. `instance.stop` убивает дерево
      `taskkill /T`, но сирота в дерево не входит. Сделать: при остановке искать
      процессы браузера по своему `user-data-dir`; таймаут кадра — отдельным
      сообщением «снимок завис», а не ошибкой сверки; один повтор кадра в новом
      процессе браузера.
- [ ] Проверить, что раннер действительно отдаёт полную историю
      (`fetch-depth: 0` добавлен): сверке нужен базовый коммит, пруфу —
      `proof.MockupRev`.
