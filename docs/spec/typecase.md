# Typecase — библиотека виджетов

Библиотека виджетов общего назначения для серверного рендеринга на Go:
типизированный вход, перечисленные состояния, собственное поведение и
инварианты, которые потребитель не может нарушить, потому что не может их
выразить.

**Имя.** *Typecase* — наборная касса: плоский ящик с ячейками, где у каждой
литеры своё гнездо, и набор собирается из готовых элементов, а не вырезается
каждый раз заново. Ровно это здесь и происходит.

**Префикс — `tc`.** Одно имя на всё: классы, шаблоны, атрибуты поведения
(L-2.3).

**Отдельный модуль.** Свой путь импорта, своя версия, свой каталог, своя
приёмка, свой жизненный цикл: собирается, проверяется и выпускается сама по
себе, а приложение подключает её версию как зависимость.

**Приложения она не знает.** Ни доменных понятий, ни маршрутов, ни данных, ни
ссылок на другие спецификации. Виджет называется по роли, а не по разделу
приложения, которое им пользуется (L-2). Этот файл — единственный из пяти,
который не ссылается ни на один другой, кроме одного: **вид задан макетом**
(`docs/visual/carrel-ui-mockups.html`, копия в модуле). Спека ссылается на
макет как на эталон вида и больше ни на что; содержимое его кадров — примеры,
а не предметная область библиотеки.

## L-1. Что это

Библиотека виджетов для интерфейсов, которые собираются **на сервере**: разметка
приходит готовой, браузер её показывает, а поведение, без которого виджет не
виджет, приезжает вместе с ним.

**Что она даёт.** Набор виджетов с типизированным входом; их стили; их поведение;
токены и две темы; набор значков. Вид каждого виджета нарисован в макете: виджет
печатает фрагмент своего кадра, а CSS библиотеки — дословный вырез CSS макета. Приложение, подключившее библиотеку, получает
интерфейс, у которого **нечего верстать**: у него есть данные и вызовы.

**Как собирается экран** — [руководство автора экрана](../guide/screen.md):
экран = кадр макета, собранный виджетами; черновик из кадра печатает
`cmd/frame2go`, данные кадра автор заменяет данными приложения.

**Чего в ней нет.** Ни маршрутов, ни данных, ни сборщика, ни внешних источников.
Никакого JavaScript-фреймворка: поведение — это несколько сотен строк, которые
библиотека кладёт рядом со своими стилями.

**Два сценария** (решение человека 2026-10-02). Ядро `tc.js` — поведение
виджетов: меню, листы, отметки, клавиши; **в ядре нет ни работы с сетью, ни
хранения**. Живой слой `tc-live.js` — необязательный, грузится после ядра, если
потребитель его попросил (`page.Document.Live`): всё, что меняет страницу без
перехода. Он делает запрос **только по адресу, который назван в разметке**
(ссылка, форма, адрес подсказок — данные потребителя), только к своему же
сайту, и кладёт пришедший HTML виджетов туда, куда указывает разметка; в
браузере хранит только то и под теми ключами, что назвал потребитель. Своих
маршрутов, формата данных и состояния приложения у слоя нет, как и у ядра; к
ядру он обращается только через `window.__tc`. Без слоя каждое его действие —
обычная ссылка или форма (U-8): страница работает переходами.

**Ради чего она существует.** Интерфейс, собранный из шаблонов, чинится плохо:
одна и та же панель, написанная в одиннадцати местах руками, расходится в
одиннадцати направлениях, и правка в одном месте ничего не говорит про
остальные десять. Виджет с инвариантами чинится в одном месте, потому что сломать
его в другом **нечем**.

## L-2. Границы и правило именования

### L-2.1 Что входит и что не входит

| Входит | Не входит |
|---|---|
| Виджеты: разметка, стиль, поведение | Маршруты и обработчики |
| Токены, темы, плотность, типографика | Данные и их формат |
| Набор значков и их подача | Состояние приложения; работа с сетью и хранение — кроме живого слоя (L-1) |
| Живой слой `tc-live.js`: запрос по адресу из разметки, ответ — HTML виджетов | Свои адреса, свой формат ответа |
| Каталог виджетов и проверки | Экраны приложения |

### L-2.2 Правило именования

**Виджет называется по роли, а не по разделу приложения, которое им
пользуется.** «Строка контакта», «панель календаря» и «плитка файла» в этой
библиотеке существовать не могут: это имена чужой предметной области, и вместе с
именем в библиотеку приезжает чужая логика.

| Так | Не так |
|---|---|
| Строка с аватаром и двумя строками текста | Строка контакта |
| Строка с ведущим значением и текстом | Строка агенды |
| Строка с галкой, текстом и сроком | Строка задачи |
| Строка с именем, размером и временем | Строка файла |

Проверяется машиной (L-8): доменное слово в имени виджета, в имени поля входа
или в имени состояния — красные ворота. Список доменных слов задаёт потребитель
при подключении; библиотека по умолчанию не пропускает имена разделов и родов
данных того приложения, для которого её собрали.

**Следствие для потребителя.** Если экрану нужен новый вид — строки, панели,
чего угодно, — это **сначала кадр в макете, потом виджет или вариант виджета в
библиотеке**, названный по роли, и только потом экран. Собственной разметки на
экране не бывает: другого места, где это можно нарисовать, нет.

### L-2.3 Пространство имён

Префикс — **`tc`**, и он один на всё: имя виджета (`tc-bar`), класс в разметке
(`.tc-bar`), имя части внутри виджета (`.tc-bar__more`), атрибут поведения
(`data-tc-open`), имя шаблона.

- **Один префикс — одно владение.** Класс с этим префиксом, написанный не
  библиотекой, ловится воротами (L-8).
- **Вариант виджета** пишется через двойной дефис: `tc-row--avatar`. Вариант —
  это другой набор ячеек при том же поведении, а не другой виджет.
- **Часть виджета** пишется через двойное подчёркивание и **снаружи не
  вызывается**: у неё нет своего входа, её данные приходят полями родителя.
- **Состояние** — `is-`: `is-open`, `is-disabled`. Состояние ставит библиотека по
  значению перечисления, а не потребитель руками.

Префикс короткий намеренно: он появляется в разметке сотни раз, и длинное имя
превращает каждый шаблон в перечисление самого себя.

## L-3. Модель компонента

Требование, из которого следует всё остальное: **потребитель не должен иметь
возможности испортить виджет**, даже по неосторожности, даже торопясь, даже не
читая этого файла.

Достигается это не соглашениями, а тем, что у него **нет средства** нарушить
правило. Шесть механизмов; каждый — правило, проверяемое воротами L-8.

### L-3.1 Шесть механизмов

**1. Вход — типизированная структура, а не слоты.**
Потребитель передаёт данные: подпись, пункты, состояние. Полей с готовой
разметкой нет ни у одного виджета; где нужна вложенность — вложенная
типизированная структура. Опечатка в имени поля становится ошибкой компиляции, а
не пустым местом на экране.

**2. Инвариант невыразим, а не «не рекомендован».**
У выпадающего меню нет поля «показывать ли стрелку»: стрелка принадлежит
виджету. Нет поля с координатами всплывающего: привязка к своему контролу
принадлежит виджету. Правило, которое можно нарушить параметром, однажды
нарушат — и не по злому умыслу, а потому что на одном экране «так было нужно».

**3. Состояния перечислены, а не собраны из флажков.**
`Open | Closed | Disabled` — одно поле с тремя значениями, а не три булевых, из
которых два могут противоречить друг другу. Невозможное состояние должно быть
невыразимым, а не «не встречающимся на практике».

**4. Геометрия — забота виджета, а вид — макета.**
Место под стрелку зарезервировано стилем самого виджета; длинная подпись
обрезается многоточием и не может налезть на стрелку ни при каком содержимом. У
потребителя нет ни одной строки стилей: ни отступов, ни ширин, ни выравнивания.

Геометрия берётся из CSS макета: стили библиотеки — дословный вырез его блока
`<style data-tc>`, и ворота сверяют их байт в байт. Виджет печатает фрагмент
своего кадра — те же теги, классы и текст, — поэтому одинаковый CSS на
одинаковом дереве даёт одинаковую картинку. Сужение экрана — тоже CSS макета:
именованные контейнеры и пороги на лестнице ширин.

**5. Поведение живёт в библиотеке.**
Открытие и закрытие, `Esc`, нажатие мимо, ходьба клавишами, возврат фокуса,
позиционирование, отступление панели под «ещё» — код библиотеки, включаемый
атрибутами, которые ставит сам виджет. Потребитель не пишет обработчиков;
встроенных скриптов нет вовсе, чтобы политика безопасности содержимого
оставалась строгой.

**6. Композиция объявлена.**
Виджет называет, что в него можно вложить, — как контейнер в настольной
библиотеке. Слот — интерфейс с неэкспортируемым методом, и его реализуют ровно
те виджеты, которые макет кладёт в этот контейнер: пары «родитель → ребёнок»
выведены из кадров. Слотов «любые виджеты» нет. Вложение, которого нет в
макете, — ошибка компиляции.

### L-3.2 Формат описания виджета

Каждый виджет в L-4 расписан по восьми пунктам. Пункт, которому нечего сказать,
пишется словом «нет» — пропуск означает, что о нём не подумали. Семь пунктов из
макета не выводятся — роль, вход, состояния, инварианты, поведение, содержимое,
чего нет; восьмой, эталон, говорит, где в макете виджет нарисован.

| Пункт | Что в нём |
|---|---|
| **Роль** | Что это и когда берут. Одна фраза |
| **Вход** | Типизированная структура: поля и их типы |
| **Состояния** | Перечисление; какое из них по умолчанию |
| **Инварианты** | Что нельзя сломать и **каким механизмом** из L-3.1 это обеспечено |
| **Поведение** | События, клавиши, фокус, что происходит при нажатии мимо |
| **Эталон** | Кадр и фрагмент макета, который виджет печатает: «кадр `s-notes-1`, фрагмент `.tc-row`». Геометрия — в CSS этого фрагмента, в описании её не пересказывают |
| **Содержимое** | Что можно вложить внутрь и в каком количестве |
| **Чего нет** | Что виджет намеренно не делает, чтобы этого не искали |

### L-3.3 Образец строки инвариантов

Чтобы формат читался однозначно, вот как выглядит пункт «Инварианты» у
выпадающего меню:

> Стрелка есть всегда — она часть виджета, поля «скрыть стрелку» не существует
> *(механизм 2)*. Всплывающее открывается под своим контролом, выровненное по его
> краю, и уходит вверх только когда снизу не помещается: координаты не
> передаются, позиционирование считает библиотека *(механизмы 2 и 5)*. Подпись
> обрезается многоточием, не доходя до стрелки: место под стрелку зарезервировано
> стилем виджета, и содержимое на него не заходит ни при какой длине
> *(механизм 4)*. Открыто и выключено одновременно — невыразимо *(механизм 3)*.
> `Esc` и нажатие мимо закрывают, фокус возвращается на контрол *(механизм 5)*.

Каждая часть этой строки — **отдельная измеряемая проверка** в L-9: не «выглядит
правильно», а измеренные прямоугольники, у которых нет пересечения, и фокус,
оказавшийся там, где обещано.

### L-3.6 Словарь и пробел в нём

Экран компонует и не изобретает. Забор: ни `.tc-` селекторов, ни `data-tc-`
селекторов, ни `style=` в коде экрана.

Когда нужной формы в каталоге нет, это пробел, и закрывается он по порядку:
**кадр в макете, затем виджет, затем экран**. Обходов на экране нет — ни сборки
из примитивов «пока библиотека не готова», ни своего типа-раскладки: такой
обход и есть та третья копия вида, из-за которой прошлые раскладки не сходились
с нарисованным.

## L-4. Состав библиотеки

### L-4.0 Как читать состав

Виджеты сгруппированы по семействам. Каждый расписан по формату L-3.2; пункт,
которому нечего сказать, помечен словом «нет». Пункт «Эталон» называет кадр и
фрагмент макета, который виджет печатает; всех форм блока — какие кадры его
рисуют — описание не перечисляет: их знает таблица эталонов, и по ней сверка
идёт форма за формой.

**Инварианты, действующие у всех и потому не повторяемые в каждом блоке:**

- у потребителя нет ни одной строки стилей и ни одного обработчика — только
  вызов и типизированные данные;
- ни одно поле входа не принимает готовую разметку;
- имя виджета, поля и состояния — по роли, без доменных слов (L-2.2);
- любой узел внутри виджета имеет своё имя: до содержимого не тянутся по
  структуре;
- цвет не бывает единственным носителем смысла: рядом с меткой всегда есть
  слово;
- виджет, у которого есть выключенное состояние, объясняет причину, а не просто
  гаснет.

**Части.** Некоторые виджеты собираются из именованных частей — они перечислены
внутри своего виджета и отдельно не вызываются. Часть не имеет своего входа: её
данные приходят полями родителя.

### L-4.1 Примитивы

#### `tc-btn` — кнопка

- **Роль.** Действие одним нажатием: подпись, значок или оба, со стрелкой, если нажатие раскрывает список.
- **Вход.** `Button{Label, Icon, IconBox, Bold, Folds, Aside, After, Tick, Menu, Kind, Small, Variant, State, Reason, Focus, Title, Submit, Href, Form, To, Name, Value, Adds, Opens, SaveAs, SaveFrom, Copy, CopyFrom, Copied, Swap, File, NoScript, Removes, Place, Secondary, Tertiary}`.
- **Состояния.** normal | icon | primary | danger | danger-solid | small | menu | folds | variant | off | disabled | focus | with-content | tertiary | link | link-off | post.
- **Инварианты.** Род, состояние и вариант — перечисления: главную тревожную кнопку, недоступную и выключенную сразу, не собрать; у кнопки без подписи есть доступное имя; кнопка печатает фрагмент своего кадра.
- **Поведение.** Нажатие — действие потребителя; кнопка со стрелкой (Menu) открывает свой список через узел меню, а не сама.
- **Эталон.** кадр `components-9`, фрагмент `.tc-btn`; формы — в таблице эталонов.
- **Содержимое.** Значок, подпись (жирная или уходящая при сужении), моноширинный хвост с текстом после, отметка перед подписью, стрелка.
- **Чего нет.** Своего цвета и своих отступов: кнопка-ссылка и кнопка отправки выглядят как любая другая; причину недоступности кнопка показывает подсказкой, а строкой под рядом — её контейнер.

#### `tc-close` — крестик

- **Роль.** Крестик, который закрывает панель, лист или сообщение.
- **Вход.** `Close{Label, Place, Href}`.
- **Состояния.** нет.
- **Инварианты.** У крестика всегда есть доступное имя — что он закрывает; крестик печатает фрагмент своего кадра.
- **Поведение.** Закрывает свой слой; Esc делает то же, фокус возвращается на вызвавший контрол.
- **Эталон.** кадр `components-33`, фрагмент `.tc-close`.
- **Содержимое.** Значок крестика, больше ничего.
- **Чего нет.** Подписи: крестик без слов, имя — в подсказке.

#### `tc-mark` — цветная метка

- **Роль.** Цветная метка источника в строке, в рейле, в заголовке.
- **Вход.** `Mark{Colour, Kind, Size, Focus}`.
- **Состояния.** one | multi | external | sized | focus.
- **Инварианты.** Цвет приходит данными и становится свойством сценарием, а не стилем в разметке; род метки — перечисление; метка печатает фрагмент своего кадра.
- **Поведение.** нет.
- **Эталон.** кадр `components-11`, фрагмент `.tc-mark`.
- **Содержимое.** нет.
- **Чего нет.** Цвет не единственный носитель смысла: рядом с меткой всегда стоит название; без сценария метка без цвета.

#### `tc-tag` — метка категории

- **Роль.** Метка категории: тег записи, фильтр по тегу, приложенная вещь, связанная запись.
- **Вход.** `Tag{Label, On, Icon, Mark, Removable, Place, Href}`.
- **Состояния.** plain | on | icon | mark | removable.
- **Инварианты.** Тег не правится на месте: он или выбран, или снимается крестиком; тег печатает фрагмент своего кадра.
- **Поведение.** Выбранный фильтр (On) снимается нажатием; тег с крестиком убирается крестиком.
- **Эталон.** кадр `s-contacts-1`, фрагмент `.tc-tag`.
- **Содержимое.** Значок или метка перед подписью, крестик после.
- **Чего нет.** Своего цвета: цвет несёт метка внутри.

#### `tc-badge` — бейдж

- **Роль.** Короткая пометка рядом с именем: «read-only», «linked ×2», «tentative».
- **Вход.** `Badge{Label, Tone, Accent, Title, Place}`.
- **Состояния.** neutral | linked | alert | local | accent.
- **Инварианты.** В бейдже есть текст; бейдж не ссылка и не кнопка; бейдж печатает фрагмент своего кадра.
- **Поведение.** нет.
- **Эталон.** кадр `components-11`, фрагмент `.tc-badge`.
- **Содержимое.** Текст.
- **Чего нет.** Действия: что с помеченным делать, говорит строка, не бейдж.

#### `tc-tick` — галка отметки

- **Роль.** Галка отметки: задача сделана, пункт списка выполнен.
- **Вход.** `Tick{Done, Variant, Glyph, Sign, Label, Send}`.
- **Состояния.** open | done | variant | glyph | sign.
- **Инварианты.** Отметка — кнопка с доступным именем, кроме знака внутри другой кнопки и знака в тексте (Sign: картинка «Done» или «Not done»); сделано или нет — одно поле; отметка печатает фрагмент своего кадра.
- **Поведение.** Нажатие переключает отметку; знак (Glyph) не нажимается: нажимается кнопка, в которой он стоит; галка дела в тексте (Sign) — тоже: заметка правится в правке (задача Carrel 99).
- **Эталон.** кадр `s-tasks-1`, фрагмент `.tc-tick`.
- **Содержимое.** нет.
- **Чего нет.** Подписи: подпись — у строки или кнопки рядом.

#### `tc-kbd` — клавиша

- **Роль.** Клавиша или сочетание в подсказке и в таблице клавиш.
- **Вход.** `Kbd{Keys, Place, Secondary}`.
- **Состояния.** нет.
- **Инварианты.** Не нажимается: это надпись, а не кнопка; клавиша печатает фрагмент своего кадра.
- **Поведение.** нет.
- **Эталон.** кадр `components-29`, фрагмент `.tc-kbd`.
- **Содержимое.** нет.
- **Чего нет.** Привязки к действию: сочетание называет клавиши, а работает поведение библиотеки.

#### `tc-num` — число рядом с подписью

- **Роль.** Число рядом с подписью: сколько записей в источнике, в разделе, в группе.

- **Состояния.** normal | alert.
- **Инварианты.** Значение — целое, а не строка; число печатает фрагмент своего кадра.

#### `tc-avatar` — аватар

- **Состояния.** initials | photo | sized | image.
- **Инварианты.** Аватар не пуст: инициалы или фотография; квадрат, размер — перечисление; аватар печатает фрагмент своего кадра.

- **Эталон.** кадр `components-12`, фрагмент `.tc-avatar`.

#### `tc-dim` — приглушённый текст

- **Роль.** Приглушённый текст рядом с главным: «· in 7 months», «412 KB», имя источника.

- **Эталон.** кадр `s-contacts-6`, фрагмент `.tc-dim`.
- **Содержимое.** Текст, жирное, моноширинный кусок, подсказка, точка состояния.

#### `tc-plain` — пояснение обычным регистром

- **Содержимое.** Только текст.

### L-4.2 Поля и формы

#### `tc-in` — поле ввода

- **Роль.** Поле ввода одной строки: текст, дата, время, поиск, пароль.
- **Вход.** `Input{Kind, Name, Value, Placeholder, Label, Mono, Focus, Error, Numeric, Disabled, Variant, Place, ReadOnly, Required, ID, Picked}`.
- **Состояния.** value | placeholder | mono | focus | error | disabled | variant.
- **Инварианты.** Плейсхолдер выглядит плейсхолдером всегда: is-ph ставит виджет, когда значения нет; род поля — перечисление; у поля есть доступное имя; поле печатает фрагмент своего кадра.
- **Поведение.** Ввод — браузера; нативный выбор даты и времени не заменяется.
- **Эталон.** кадр `components-10`, фрагмент `.tc-in`.
- **Содержимое.** нет.
- **Чего нет.** Своей подписи: подпись — у поля формы (tc-field), вокруг.

#### `tc-in` — поле со списком

- **Роль.** Поле со списком: значение выбирают из списка, а не набирают.
- **Вход.** `Pick{Value, Mark, Aside, Unset, Label, Focus, Variant, Place, Name, Options}`.
- **Состояния.** value | unset | aside | focus | variant | select.
- **Инварианты.** Стрелку рисует система (is-pick), иначе список неотличим от строки ввода; пустой выбор выглядит плейсхолдером; выбор печатает фрагмент своего кадра.
- **Поведение.** Нажатие открывает список под полем; выбор закрывает его, фокус возвращается на поле.
- **Эталон.** кадр `components-10`, фрагмент `.tc-in.is-pick`.
- **Содержимое.** Приглушённое пояснение после значения.
- **Чего нет.** Набора с клавиатуры: чтобы искать, есть фильтр списка.

#### `tc-in` — фильтр списка

- **Роль.** Фильтр списка: значок поиска и строка запроса в одной рамке.
- **Вход.** `Filter{Query, Waiting, Quiet, Variant, Place, Action, Hidden}`.
- **Состояния.** waiting | quiet.
- **Инварианты.** Значок — первый узел поля, строка занимает остаток; фильтр печатает фрагмент своего кадра.
- **Поведение.** Сужает список по мере набора; Esc очищает.
- **Эталон.** кадр `s-contacts-1`, фрагмент `label.tc-in`.
- **Содержимое.** Строка запроса.
- **Чего нет.** Подсказок по мере набора: это поиск в шапке, а не фильтр.

#### `tc-in` — поле тегов

- **Роль.** Поле, в котором выбранное стоит тегами, а новое набирают тут же: связанные записи, получатели письма.
- **Вход.** `TagInput{Parts, Wrap, Focus, Columns, Name, Add}`; строка набора — `TagAdd{Name, Placeholder, Label, Value, Suggest, Options}`.
- **Состояния.** tags | wrap | focus.
- **Инварианты.** Выбранное — теги, их снимают крестиком, а не правят; поле печатает фрагмент своего кадра.
- **Поведение.** Набор открывает подсказки под полем; выбор добавляет тег; Backspace в пустой строке снимает последний. Подсказки по `Suggest` спрашивает живой слой (tc-live.js). Без сценариев у строки — список браузера (`datalist`) из `Options`: значение уходит (UID записи, адрес), подпись видна рядом (задача Carrel 96); где подсказывает сервер, живой слой этот список убирает.
- **Эталон.** кадр `s-tasks-3`, фрагмент `span.tc-in.tc-in--tags`.
- **Содержимое.** Теги и набранный текст.
- **Чего нет.** Ввода UID руками вне подсказок: его пункт стоит в конце списка подсказок.

#### `tc-in` — многострочное поле

- **Роль.** Многострочное поле: примечание к записи, текст документа, заголовок, который растёт.
- **Вход.** `Area{Name, Text, Variant, Mono, Focus, Label}`.
- **Состояния.** plain | title | body | letter | paste | tall | focus.
- **Инварианты.** Текст — как есть, с переводами строк; поле растёт по содержимому, а не прокручивается внутри; поле печатает фрагмент своего кадра.
- **Поведение.** Ввод — браузера.
- **Эталон.** кадр `s-contacts-3`, фрагмент `textarea.tc-in`.
- **Содержимое.** нет.
- **Чего нет.** Разметки: кнопки полосы правки вставляют символы Markdown в текст.

#### `tc-q` — строка запроса

- **Роль.** Строка запроса внутри поля поиска или фильтра.
- **Вход.** `Query{Value, Placeholder, Label, Name}`.
- **Состояния.** нет.
- **Инварианты.** Тип поля — search; у строки есть доступное имя; строка печатает фрагмент своего кадра.
- **Поведение.** Ввод — браузера; Esc очищает, если поле не пусто.
- **Эталон.** кадр `shell-1`, фрагмент `.tc-q`.
- **Содержимое.** нет.
- **Чего нет.** Рамки и значка: их рисует поле вокруг.

#### `tc-seg` — сомкнутый переключатель

- **Роль.** Сомкнутый переключатель: один из нескольких вариантов, все на виду.
- **Вход.** `Seg{Options, Variant, Place, Secondary, Name, Theme, Multiple, Swap}`.
- **Состояния.** default | start | compact | icons | radio | links | several.
- **Инварианты.** Выбран ровно один вариант, у ряда флажков (Multiple) — любые; у варианта без подписи есть доступное имя; переключатель печатает фрагмент своего кадра.
- **Поведение.** Нажатие выбирает вариант; стрелки ходят по вариантам внутри переключателя.
- **Эталон.** кадр `components-13`, фрагмент `.tc-seg`.
- **Содержимое.** Варианты: подпись, значок или оба, число; вариант — кнопка, радио формы или ссылка.
- **Чего нет.** Выпадающего списка: вариантов столько, сколько помещается; тесно — SegFold, больше — выбор (Pick).

#### `tc-segfold` — сегмент, которому тесно

- **Роль.** Сегмент, которому тесно: на широкой полосе — сомкнутый переключатель ссылок, на узкой — выпадающий выбор с текущим вариантом (решение 30.09.2026).
- **Вход.** `SegFold{Seg, Phone}`.
- **Состояния.** default.
- **Инварианты.** Выбран ровно один вариант; у каждого варианта адрес; складывается там же, где полоса прячет второстепенное (is-2nd); виджет печатает фрагмент своего кадра.
- **Поведение.** На узкой полосе нажатие на текущий вариант открывает меню остальных (details, без сценария); выбор — переход по ссылке. Короткий переключатель (`Phone`) складывается только на полосе телефона, 640&nbsp;px и уже: Day / Week / Month / Range агенды.
- **Эталон.** кадр `s-contacts-7`, фрагмент `.tc-segfold`.
- **Содержимое.** Варианты: подпись и число; сегмент и меню из одних и тех же вариантов.
- **Чего нет.** Кнопок и радио: вариант сложенного сегмента — всегда ссылка.

#### `tc-check` — флажок с подписью

- **Роль.** Флажок с подписью: включено или нет.
- **Вход.** `Check{On, Parts, Label, Tertiary, Name, Value, Disables, Radio}`.
- **Состояния.** on | off | rich | tertiary | box.
- **Инварианты.** Включено или нет — одно поле; флажок — кнопка с подписью или флажок формы (Name), у него есть доступное имя; флажок печатает фрагмент своего кадра.
- **Поведение.** Нажатие переключает; пробел — тоже. Флажок формы с `Disables` гасит, пока отмечен, поля формы с этими именами — имена через пробел, как классы: All day гасит «start.time due.time» (задача Carrel 111); гасит сценарий ядра.
- **Эталон.** кадр `components-10`, фрагмент `.tc-check`.
- **Содержимое.** Подпись: текст, приглушённое пояснение, моноширинный кусок, бейдж, число внутри фразы, сторона конфликта.
- **Чего нет.** Третьего состояния: частичный выбор — у строки источника (tc-tickrow), не у флажка.

#### `tc-checkform` — отметка полосы формой

- **Роль.** Отметки полосы, которые сами — форма: «Compact rows», «Events · Tasks due · Notes» уходят GET-запросом с остальными выборами списка.
- **Вход.** `CheckForm{Checks, Action, Hidden, Apply, Tertiary}`.
- **Состояния.** default.
- **Инварианты.** Отметки — флажки формы (Check.Name); форма отправляет её и скрытые поля; без сценария — кнопкой Apply, со сценарием — при смене; виджет печатает фрагмент своего кадра.
- **Поведение.** Смена отметки отправляет форму (сценарий); без сценария — Apply рядом.
- **Эталон.** кадр `s-contacts-1`, фрагмент `.tc-checkform`.
- **Содержимое.** Флажок с подписью, скрытые поля, Apply для работы без сценария.
- **Чего нет.** Своего вида: вид у флажка; Apply виден, только пока страница без сценария (data-tc-noscript на html, его снимает tc.js).

#### `tc-range` — диапазон дат

- **Роль.** Диапазон дат: два поля, стрелка между ними и кнопка, которая показывает.
- **Вход.** `Range{From, To, Show, Wrap, Secondary, Action}`.
- **Состояния.** default | wrap | form.
- **Инварианты.** Начало — слева, конец — справа, между ними стрелка; диапазон печатает фрагмент своего кадра.
- **Поведение.** Show применяет диапазон; Enter в поле — то же. С адресом (Action) диапазон — форма GET: From и To уходят полями, Show её отправляет, без сценария.
- **Эталон.** кадр `components-18`, фрагмент `.tc-range`.
- **Содержимое.** Два поля и кнопка.
- **Чего нет.** Выбора диапазона в одном поле: две даты — два поля.

#### `tc-field` — поле формы

- **Роль.** Поле формы: подпись и контролы под ней, подсказка о том, что значит значение.
- **Вход.** `Field{Label, LabelAside, LabelSpan, Parts, Width, Gap, OwnLine, Place, Action}`.
- **Состояния.** labelled | bare | hint | group | swatches | zoom | photo | row | own-line.
- **Инварианты.** Ширина — перечисление: поле даты не растягивается, растягивается поле тегов; подпись связана с контролом; поле печатает фрагмент своего кадра.
- **Поведение.** нет: поведение у контролов.
- **Эталон.** кадр `components-10`, фрагмент `.tc-field`.
- **Содержимое.** Контролы (ввод, выбор, текст, теги, сегмент, флажки, кнопки, строка), подсказка, образцы цвета, масштаб, ряд меток, группа флажков, фотография.
- **Чего нет.** Проверки значения: что неверно, говорит подсказка, которую ставит экран.

#### `tc-fset` — группа полей

- **Роль.** Группа полей формы под рубрикой: «Phone numbers», «Email», «Password».
- **Вход.** `FieldSet{Rubric, Items, Variant}`.
- **Состояния.** plain | lead.
- **Инварианты.** Рубрика — первой, поля — после неё; первая группа формы без линейки сверху; группа печатает фрагмент своего кадра.
- **Поведение.** нет.
- **Эталон.** кадр `s-contacts-3`, фрагмент `.tc-fset`.
- **Содержимое.** Поля, кнопки, строки, переносы, сетка выбора, сообщение, таблица.
- **Чего нет.** Сворачивания: группа всегда открыта.

#### `tc-form` — форма

- **Роль.** Форма: поля и группы полей, которые переносятся по ширине.
- **Вход.** `Form{Items, Variant, Tight, Action, Method, Fields, ID}`.
- **Состояния.** plain | tight | flush | column | columns | action.
- **Инварианты.** Поля переносятся, а не сжимаются; отступы формы — перечисление; форма печатает фрагмент своего кадра.
- **Поведение.** Enter в поле формы отправляет форму.
- **Эталон.** кадр `s-agenda-3`, фрагмент `.tc-form`.
- **Содержимое.** Поля, группы полей, флажки, ряды полей, колонки.
- **Чего нет.** Кнопок сохранения: они в шапке экрана или в подвале формы (tc-formfoot).


#### `tc-post` — форма отправки

- **Роль.** Форма POST без полей на виду: её отправляет кнопка, стоящая где угодно на странице, по её имени (Button.Form).
- **Вход.** `PostForm{ID, Action, Fields, File}`.
- **Состояния.** default.
- **Инварианты.** Форму не видно: в ней только скрытые поля; форма печатает фрагмент своего кадра.
- **Поведение.** Отправку делает браузер — сценарий не нужен.
- **Эталон.** кадр `components-37`, фрагмент `.tc-post`.
- **Содержимое.** Скрытые поля.
- **Чего нет.** Видимых полей и кнопок: кнопка стоит там, где её место, — в полосе, в строке, в меню.
#### `tc-formfoot` — подвал формы

- **Роль.** Подвал формы: сохранить, отменить и что ещё сделать с формой целиком.
- **Вход.** `FormFoot{Items, Variant}`.
- **Состояния.** plain | flush | no-rule | wrap.
- **Инварианты.** Главная кнопка — первой; подвал печатает фрагмент своего кадра.
- **Поведение.** нет: поведение у кнопок.
- **Эталон.** кадр `s-contacts-5`, фрагмент `.tc-formfoot`.
- **Содержимое.** Кнопки, прижатая группа, приглушённое пояснение.

### L-4.5 Наложения

#### `tc-menu` — меню

- **Роль.** Меню: действия с записью, выбор значения, куда записать, подсказки поиска, настройка колонок.

#### `tc-drop` — кнопка с меню под ней

## L-5. Токены и темы

Единственное место, где потребитель влияет на внешний вид. Всё остальное —
внутреннее дело виджета.

### L-5.1 Что переопределяется

| Что | Как |
|---|---|
| Палитра | Именованные значения: чернила, поверхность, фон, подложка, разделитель, приглушённый текст, акцент, отказ, кромка, волосная линовка, пыльный текст |
| Типографика | Три семейства: заголовочное, интерфейсное, моноширинное; и базовый кегль |
| Плотность | Два значения высот строк; третьего не заводится |
| Поле страницы | Горизонтальный отступ панелей, строк и шапок: 20 px, в узкой раскладке 14 px |
| Значки | Набор подставляется потребителем: библиотека даёт подачу, а не рисунки |
| Радиус и толщина линовки | Два радиуса (3 px и 2 px) и одна толщина линовки |

Токены раскладки — ширина рейла `--tc-rail`, панели `--tc-side`, высота верхней
полосы `--tc-top` — токенами называются, но это геометрия: они не
переопределяются (L-5.2).

Переопределение — **значения**, а не правила: подставляется цвет, но не то, где
он применяется. Виджет, которому не хватило значения, не рисуется, а падает при
сборке: молча взятое умолчание — это расхождение, которое обнаружат на экране.

### L-5.2 Что не переопределяется никогда

- **Геометрия виджета**: отступы, зарезервированные места, ширины полей по роду,
  высоты строк по виду, пороги отступления панелей, токены раскладки
  (`--tc-rail`, `--tc-side`, `--tc-top`).
- **Поведение**: открытие, закрытие, фокус, клавиши, позиционирование.
- **Состав**: наличие стрелки у меню, метки у строки, причины у выключенного.

Это и есть граница между «оформить» и «сломать». Всё, что можно подставить,
подставляется значением; всё, что можно испортить, снаружи недостижимо.

### L-5.3 Две темы

Тема — состояние корня документа: светлая, тёмная или следование системе. Между
темами меняются **только значения палитры**: ни один виджет не меняет состав,
геометрию и поведение в тёмной теме.

**Тема применяется до первой отрисовки.** Иначе страница успевает моргнуть
светлым. Для этого библиотека отдаёт короткий сценарий, который обязан
выполниться раньше отрисовки; встроенным блоком он быть не может, потому что
политика безопасности содержимого не допускает встроенных сценариев — и это
осознанный размен, а не неудобство.

Хранение выбора темы — дело потребителя. Библиотека читает состояние и умеет его
переключать; где оно лежит между заходами, она не знает.

## L-6. Поведение

### L-6.1 Как оно включается

Сценарий библиотеки находит виджет по тому, что виджет и так печатает: по
классам и строению фрагмента из макета — кнопка выпадашки есть первый ребёнок
`.tc-drop`, её меню стоит рядом; лист — `.tc-sheet` на `.tc-scrim`; крестик —
`.tc-close`. Своих крючков у поведения почти нет: `data-tc-colour` и
`data-tc-width` (данные), `data-tc-open` (кнопка, открывающая лист на месте, —
поле `Opens`; у навигации — текущий раздел, который в рейле из значков
открывает лист своих источников, а в остальных состояниях остаётся ссылкой)
и то, что пишет сам сценарий: `data-tc-mode` на корне оболочки,
`data-tc-overflow` на баре, который CSS не уместил. Потребитель не пишет ни
строчки: у него нет ни события, ни обработчика; что открыть, он называет полем
виджета.

- **Встроенных сценариев нет ни одного.** Ни атрибутов-обработчиков, ни блоков
  внутри разметки. Политика содержимого может быть строгой только при этом
  условии, и именно она — главная защита от чужого текста на странице.
- **Один файл поведения** на всю библиотеку, рядом со стилями, из того же
  модуля. Внешних источников нет. Правил CSS он не добавляет: закрытое — это
  атрибут `hidden` (и встроенный `display:none` из сценария там, где правило
  макета показало бы элемент всё равно), потому что у кадров макета закрытого
  состояния нет — они рисуют открытое.
- **Виджет работает и без сценариев** настолько, насколько это возможно: то, что
  без них невозможно, названо в его пункте «Чего нет», а не тихо отсутствует.
  **Цвет метки** приходит данными (`data-tc-colour`) и становится свойством
  `--tc-colour` только через сценарий: `style=` запрещён политикой
  содержимого. **Закрытое меню и закрытый лист** без сценария не открыть: экран
  тогда открывает лист своим адресом, а меню рисует открытым. **Режим
  оболочки** (`full`, `rail`, `drawer`) задаёт CSS макета свойством
  `--tc-shell-mode`; сценарий только читает его, своего порога у него нет.
  **Страховка переполнения бара** — замер, который включается, когда
  содержимое не влезло после правил CSS: бар помечается и прокручивается вбок;
  без сценария бар отдаёт кнопки только по порогам CSS. На содержимом эталонов
  она не срабатывает ни на одной ступени: что не влезло, CSS отдаёт в «⋯»
  (`is-2nd`, на телефоне `is-3rd`).

### L-6.2 Клавиши и фокус

Общие правила, действующие у всех виджетов:

| Правило | Почему |
|---|---|
| `Esc` закрывает верхнее наложение и только его | Иначе одно нажатие уносит несколько слоёв разом |
| Фокус заперт внутри открытого наложения | Уехавший за спину фокус — потерянный человек |
| При закрытии фокус возвращается на вызвавший контрол | Возврат «в начало страницы» теряет место работы |
| Ходьба стрелками — внутри виджета, `Tab` — между виджетами | Список из сорока пунктов не должен требовать сорока нажатий `Tab` |
| Ни одна клавиша не срабатывает, пока курсор в поле ввода | Буква, стирающая запись, — не сокращение |
| Ни одна клавиша не делает ничего разрушительного | Разрушение подтверждают, а не нажимают вслепую |

### L-6.3 Доступность

Не отдельный раздел работ, а часть каждого виджета: доступное имя у всего, что
нажимается; связь подписи с полем; объявленная роль у наложений; видимый фокус,
который не убирается ради вида; отношение контраста, проверяемое машиной (L-9).

Виджет без доступного имени не проходит ворота (L-8) — это дешевле, чем
проходить по библиотеке потом.

## L-7. Композиция

**Виджет объявляет, что в него можно вложить.** Это то же, что список допустимых
детей у контейнера в настольной библиотеке, и то же, что пункт «Содержимое» в
описании каждого виджета (L-3.2).

- Вложение объявленного рода — обычная типизированная структура.
- Вложение **необъявленного** рода — ошибка компиляции, а не странный вид.
- Сырой разметки не принимает ни один виджет: поля `string` / `HTML` нет.
- Слот — интерфейс с неэкспортируемым методом (`Block`, `Control`, `RailPart`,
  `SheetPart`…). Его реализуют ровно те виджеты, которые макет кладёт в этот
  контейнер: пары «блок-родитель → блок-ребёнок» выведены из всех кадров, и тест
  сверяет их с типами в обе стороны — лишнее разрешение так же красное, как
  недостающее. Слотов «любые виджеты» нет.
- Порядок детей, который макет закрепляет (шапка: заголовок, затем действия;
  лист: голова, тело, подвал), задан полями структуры, а не срезом.

**Новый род содержимого заводится в макете, потом в библиотеке**, а не на
стороне потребителя: кадр показывает, куда он кладётся, тип объявляется и
реализует интерфейс этого слота, запись добавляется в каталог. Пока этого не
сделано, положить туда нечего — и это не помеха, а то, ради чего всё устроено
(L-3.6).

**Глубина ограничена.** Наложение в наложении, меню в меню, дерево в дереве —
невыразимы. Случай, где это кажется нужным, — почти всегда экран, который надо
было разделить.

## L-8. Ворота

Проверки, которые обязаны быть красными, когда правило нарушено. Каждая —
исполняемая; ни одна не заменяется договорённостью.

| Ворота | Имя | Что не пропускают |
|---|---|---|
| **CSS из макета** | `css-from-mockup` | `css/typecase.css` и `icons/sprite.svg`, разошедшиеся с блоком `<style data-tc>` и спрайтом макета хоть на байт; CSS интерфейса вне `css/` — правило, чей объект — класс `tc-*` |
| **Эталоны** | `widget-fragments` | Запись таблицы эталонов, чей вывод не совпадает с фрагментом кадра: тег, классы, текст, значения полей, значки, данные — первым расходящимся путём |
| **Пары контейнеров** | `container-pairs` | Вложение, которое макет рисует, а тип контейнера не принимает, и вложение, которое тип принимает, а макет не рисует; слот, принимающий любой виджет |
| **Покрытие кадров** | `frame-coverage` | Кадр-маршрут макета (Р-16, `docs/development.md`: без пометки «компонент», «фрагмент», «список», «меню», «кандидат»), у которого нет ни экрана демо, ни строки в `docs/visual/gaps.md`; экран или пробел, не являющийся кадром-маршрутом; кадр, который и собран, и записан пробелом |
| **Владение** | `ownership` | Имя из пространства библиотеки, написанное не библиотекой |
| **Имена узлов** | `node-names` | Элемент в выводе эталона без класса библиотеки (`tc-*`, `is-*`), кроме исключений словаря макета: строчные текстовые теги, `svg` и его внутренности, теги, закреплённые смыслом внутри блока |
| **Типизированный вход** | `typed-input` | Поле входа, принимающее готовую разметку; поле, тип которого позволяет молча уронить значение при сборке |
| **Перечисления** | `enumerations` | Два и более булевых поля там, где состояние одно; состояние, выразимое противоречиво |
| **Именование по роли** | `domain-naming` | Доменное слово в имени виджета, поля или состояния (L-2.2) |
| **Формат описания** | `doc-format` | Виджет, у которого не заполнены все восемь пунктов L-3.2, последний из них — «Эталон»; «Вход», расходящийся с полями типа |
| **Каталог** | `catalog` | Состояние из описания виджета без эталона; строка таблицы шире её шапки |
| **Спека** | `spec-l4` | Виджет, которого нет в L-4, и описание в L-4, которого нет в коде |
| **Проверяемость** | `verifiable` | Инвариант без исполняемой проверки; проверка L-9.2 без сломанной фикстуры; ворота, не подключённые к прогону |
| **Без встроенного** | `no-inline` | Обработчик в атрибуте, блок сценария или стиля внутри разметки |
| **Доступность** | `a11y` | Нажимаемый узел без доступного имени; поле без связанной подписи; нажимаемый узел внутри ссылки или кнопки |
| **Страница демо** | `screens-css` | Стили страницы демо-экранов, задевающие виджеты: экран — это CSS библиотеки и ничего больше |
| **Кусачесть** | — | Проверка, которая ни разу не была показана красной (L-9.3): у каждых ворот есть свой укус |
| **Формат кода** | `gofmt`, `vet` | Неотформатированный исходник, замечания `go vet` |

Линт макета (`mockup-lint`, правила — `docs/visual/mockup.md`, «Проверки») —
ворота самого макета: библиотека берёт из него CSS и эталоны и верит ему,
потому что его держат эти правила.

## L-9. Каталог и проверка поведения

### L-9.1 Каталог живых виджетов

Одна страница, на которой стоит **каждый виджет в каждом своём состоянии**.
Собирается из того же модуля, что и библиотека, запускается одной командой и не
требует ни приложения, ни данных.

Каталог — не витрина, а рабочий инструмент: по нему сверяют вид, на нём гоняют
проверки поведения, в него смотрят, когда выбирают виджет. Виджет, которого в
каталоге нет, считается несуществующим (L-8).

Вторая страница каталога — **тот же набор без сценариев**: видно, что работает
без них, а что честно названо недоступным.

Ячейка каталога — фрагмент виджета из его эталона: по записи на состояние и
вариант. Рядом с виджетом стоят кадры макета с пометкой «компонент»,
«фрагмент», «список», «меню», собранные вокруг него, — как их рисует макет.
Ширину ячеек задаёт переключатель с той же лестницей ширин, что у страницы
макета и у проверок в браузере; тему — ссылки светлой и тёмной темы.

### L-9.2 Что проверяется в браузере

Половина того, что делает виджет, вычисляется: цвет, высота, положение
всплывающего, дошло ли нажатие. Разметка, прочитанная без браузера, об этом не
говорит ничего. Поэтому проверки идут в настоящем браузере и **измеряют**:

| Что меряется | Пример проверки |
|---|---|
| Пересечения | Прямоугольник подписи не пересекается с прямоугольником стрелки ни при какой длине подписи |
| Привязка | Левый край всплывающего совпадает с краем контрола; низ контрола совпадает с верхом всплывающего |
| Переворот | У нижнего края окна всплывающее уходит вверх и остаётся целиком видимым |
| Обрезание | Длинная подпись заканчивается многоточием, а не выходит за свою ячейку |
| Одна строка | Панель при любой ширине занимает ровно одну строку; лишнее ушло под «ещё» |
| Зона нажатия | В узкой раскладке высота зоны не меньше 44 px |
| Фокус | После закрытия наложения фокус на вызвавшем контроле |
| Клавиши | `Esc` закрывает верхний слой и не трогает нижний |
| Контраст | Отношение контраста текста к фону в обеих темах не ниже порога |
| Тема | Между темами меняются значения цвета и **не меняются** прямоугольники |

### L-9.3 Проверка, которая кусает себя

Автоматическая проверка, ни разу не показанная красной, ничего не гарантирует.
Поэтому у набора проверок есть свой набор: он **ломает каждый инвариант по
очереди** и требует, чтобы соответствующая проверка покраснела. Не покраснела —
красные ворота у самого набора.

Это дороже, чем кажется, и дешевле, чем интерфейс, который «проверяется», а на
деле нет.

## L-10. Версионирование и совместимость

Версия по правилам семантического версионирования; потребитель подключает точную
версию и обновляется осознанно.

**Что считается ломающим изменением:**

- убрано или переименовано поле входа, состояние, виджет или его вариант;
- поле стало обязательным или сменило тип;
- изменился состав допустимого содержимого;
- изменилось поведение, описанное в пункте «Поведение», или инвариант из пункта
  «Инварианты»;
- изменилось имя в пространстве имён библиотеки.

**Что ломающим не считается:** новый виджет, новое состояние у существующего
виджета, новое необязательное поле, правка внутренней геометрии, не меняющая
инвариантов, исправление, приводящее виджет в соответствие его же описанию.

**До 1.0.** Ломающее изменение допустимо в минорном выпуске и без периода
устаревания: старое удаляется сразу, переходных слоёв и псевдонимов нет. Журнал
изменений говорит, что изменилось, без руководства по переходу.

**С 1.0 — устаревание.** Поле или виджет сначала помечается устаревшим и
продолжает работать не меньше одного минорного выпуска; в журнале изменений
сказано, чем заменять. Удаление — только в мажорном выпуске.

**Журнал изменений** ведётся по выпускам и говорит, что делать потребителю, а не
что сделал автор.

## L-11. Поставка и приёмка

### L-11.1 Поставка

- Всё — внутри модуля: разметка, стили, сценарий поведения, набор значков,
  шрифты. Сборщика нет, внешних источников нет, готовых файлов сборки в
  репозитории нет: они расходятся с исходниками, и этого никто не замечает.
  **Исключение одно — `css/typecase.css`**, вырез CSS макета: ворота
  `css-from-mockup` сверяют его с макетом байт в байт, поэтому незаметно
  разойтись он не может.
- Стили собираются при запуске из своих файлов в объявленном порядке.
- Лицензия — открытая, совместимая с использованием в приложении; текст лежит в
  модуле.
- В коде, который получает потребитель, зависимостей за пределами стандартной
  библиотеки нет. Новая — решение, а не удобство. Проверки во `internal`
  (браузер, разбор HTML) могут их иметь: потребитель их не импортирует.

### L-11.2 Библиотека готова, когда

- каждый виджет из L-4 существует, описан по всем восьми пунктам и стоит в
  каталоге во всех своих состояниях;
- у каждого инварианта есть исполняемая проверка, и она была показана красной;
- все ворота L-8 зелёные;
- каталог работает и со сценариями, и без них;
- обе темы проходят проверку контраста;
- узкая раскладка проходит проверку зон нажатия;
- выпущена версия, и журнал изменений говорит, что в ней.

Приёмка библиотеки **не требует приложения**: ни его данных, ни его экранов, ни
его сервера. Библиотека, которую нельзя принять отдельно, — не библиотека.
