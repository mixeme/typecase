# framegen — экран из кадра макета

Генератор демо-экранов плана 3 (шаг 1): переводит кадр макета
`docs/visual/carrel-ui-mockups.html` в функцию экрана — дерево виджетов
`widget` с данными кадра, сверху вниз — и пишет их в `internal/screens`, файл
на раздел макета. Верен ли перевод, говорит статическая сверка
(`internal/screens`, `TestFramesStatic`): дерево экрана равно дереву кадра.

Сохранён по поручению владельца (2026-09-26): тот же перевод — первый
черновик каждого экрана клиента Carrel. На Go он переписывается шагом 5
плана 3 (`cmd/frame2go`); после этого каталог удаляется.

## Запуск

```sh
sh tools/framegen/run.sh
```

Перегенерирует `internal/screens`, прогоняет сверку и печатает, что ещё
расходится, по видам. Нужны Python 3 и Go. Промежуточное — в `out/`
(`FRAMEGEN_OUT`): журнал генерации (`gen.log`, строки `GAP` — кадры, которые
не собрались, и почему), все расхождения (`diffs.txt`).

## Как устроен

- `genrows.py` … `gencards.py` — генераторы эталонов плана 2, по семейству
  виджетов, каждый подключает предыдущий через `exec`: `genrows` → `genshell`
  → `genhead` → `genmain` → `genmenu` → `gensheet` → `gendoc` (с `rawlib`) →
  `gencards` → `genfinal`. Они писались под сверку одного виджета с его
  фрагментом и местами ставят заглушки вместо детей.
- `gsfix.py`, `gsfix2.py` — переопределения для целых кадров: каждый вариант и
  каждый ребёнок как нарисован. Подключаются после цепочки и заменяют её
  функции по имени.
- `enums.py` — таблицы вариантов из самих виджетов: для каждого перечисления с
  методом `class()` — какая константа печатает какие классы. Генератор
  выбирает вариант по классам элемента, а не по своему списку.
- `genscreens.py` — берёт кадры-маршруты (решение Р-16: без пометки
  «компонент», «фрагмент», «список», «меню», «кандидат»; меню приложения и
  трея — в каталог), снимает рамку окна (`mk-*`), как её снимает сверка, и
  переводит корень кадра. `emitscreens.py` пишет Go.
- `cats.py` — сводка расхождений по видам.

## Чем плох

Цепочка скриптов через `exec`, глобальные имена, переопределения поверх
переопределений: это инструмент одного человека, пока он доводит экраны.
Где в кадре данные, а где разметка, генератор не знает — строки списка
для него просто строки, а не цикл по модели.
